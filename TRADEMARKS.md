## What you may do

- Use, change and redistribute the code under the Apache License 2.0.
- Say truthfully what your work relates to, for example "based on Remyral", "a fork of Remyral" or "compatible with
  Remyral".
- Keep technical identifiers that appear in the code where changing them would break compatibility: package names
  (`@remyral/*`), protocol and signing contexts (for example `remyral-worker-release/v1`), environment variable
  prefixes, file and service names.

## What you should not do

- Distribute a build, image, installer or hosted service under the name Remyral or Remana, or with their logos. A fork
  that is distributed uses its own name and logo (replace the brand assets listed above).
- Point a distributed fork at Remana's update channel or release keys. A fork ships its own release keys, version
  catalog and update channel.
- Suggest that Remana made, endorses or supports your build or service when it does not.
