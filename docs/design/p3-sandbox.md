# Design note: `p3-sandbox` — execution profiles

- **Task:** `p3-sandbox` — sandbox profiles: Linux `container`, `runtime-sandbox` pass-through, macOS/Windows/Pi `host-restricted`; profile selection; escape test suite.
- **Date:** 2026-10-13
- **Binding inputs:** ADR-0007 (profiles; dedicated low-privilege OS user mandatory on macOS/Windows/Pi; refuse what cannot be provided), ADR-0008 (truthful capabilities), ADR-0010 rule 3 (untrusted ⇒ `container`, egress = model API only), ADR-0012 rules 2–4, docs/compat/README.md §4.6, threat model T-SBX-1..5, T-INJ-1, p3-workspace-and-secrets.md (the shared-mirror gap).

### Spawner hook

`spawnOwnedProcess({ …, confiner })`: the adapter builds command/args/env as usual; the confiner rewrites the plan (`docker run … image cmd`, `sandbox-exec -p … /bin/sh -c 'ulimit …; exec "$@"' cmd`, `remyral-jobrun.exe … -- cmd`) and may supply its own `ProcessTreeKiller` (a container is killed through the engine; killing the client alone leaves it running) and a `dispose`. The rewritten argv is checked again for secret values; secrets reach `docker run` only as `--env NAME` with the value in the client's environment. `OwnedProcess.dispose()` (new) kills what is left of the tree — also after a normal leader exit — and removes the confinement's resources. `ProcessTreeKiller.kind` gained `container` and `windows-job-object`.

`SandboxRunner` = `{ profile, kind, confiner(ctx), launch(req) }`; `launch` returns the `OwnedProcess`. Adapters that spawn themselves (Claude Agent SDK custom spawn, Codex app-server) take `runner.confiner(ctx)`.

## Decisions

1. **Cross-attempt git isolation (T-SBX-4).** The agent never gets write access to any git metadata the worker later runs git against. Each attempt gets its own git dir `<root>/sandboxes/<job>/<attempt>/git` (HEAD on `rac/<job>/<attempt>` at the base commit, index of the base tree, `objects/info/alternates` → the mirror's object store). Container: the worktree is mounted rw at `/workspace`, a file `gitdir: /remyral/git` is bind-mounted **read-only over `/workspace/.git`**, the git dir rw at `/remyral/git`, the mirror object store read-only at its host path (so `alternates` resolves); nothing else of the root is mounted. Seatbelt: `GIT_DIR`/`GIT_WORK_TREE` point at the view; writes to the mirror, other attempts and the worktree's `.git` file are denied. The agent's commits are scratch: the worker records the result with its own `WorkspaceManager.commit()` (`git add -A` of the final tree + attempt trailer), so refs/config the agent wrote are never honoured. `snapshotTrustedGit()` / `assertTrustedGitUnchanged()` hash the `.git` file, mirror config, worktree metadata and the attempt branch around the run and refuse on change (detection for profiles that cannot prevent it).
   *Rejected:* `git clone --shared` per attempt with push from the clone — the worker would push and secret-scan inside a repository whose config the agent controls. *Rejected:* per-attempt OS identity — needs admin rights to create users at job time.
   *Cost:* the agent's own commit history/messages are not kept (one worker commit per attempt).
2. **`container`** (Linux, rootless Docker/Podman): one container per runtime process from a pinned image, `--pull never`, `--init`, `--read-only`, `--cap-drop ALL`, `--security-opt no-new-privileges`, default seccomp (never `unconfined`), non-root `--user 10001:10001` (root refused in the argv builder), `--pids-limit`, `--memory` = `--memory-swap`, `--cpus`, `nofile`/`fsize`/`core=0` ulimits, tmpfs `/tmp` and `HOME` (nosuid,nodev), `--ipc private`, `--log-driver none` (secrets the agent prints never land in engine log files), `--mount` (a missing source is an error), no engine socket, no published ports, no host namespaces. Readiness: Linux only, rootless only, images present locally (`check()` → `ProfileCapability`). Docker Desktop on macOS is accepted only with the test/dev flag `allowNonLinuxHost`.
3. **Egress.** `none` ⇒ `--network none`. `allowlist` ⇒ a per-job `--internal` network (no route out, no external DNS) shared only with a per-job proxy sidecar (`remyral/egress-proxy`, read-only, no caps, 128 MiB, 64 pids) that is additionally connected to the egress network. The proxy accepts only `CONNECT host:port` for exact allowlisted pairs, refuses IP literals and plain HTTP, resolves DNS itself and refuses if **any** resolved address is loopback/private/link-local (169.254.169.254)/CGNAT/multicast/ULA/NAT64/v4-mapped, then connects to the checked address (no re-resolution ⇒ no DNS rebinding); bounded tunnels, header size/time, idle timeout; one JSON decision line per request (no payload). The job gets `HTTPS_PROXY`/`HTTP_PROXY` and `NODE_USE_ENV_PROXY=1`. Default allowlist: `api.anthropic.com`, `api.openai.com` (config `sandbox.egressAllow`).
4. **`host-restricted`.** Requires a verified dedicated worker user (`verifyWorkerIdentity`): refused for root/SYSTEM, members of `admin`/`sudo`/`wheel`/`root`/`docker`/`lxd`/`libvirt`/`disk`/BUILTIN\Administrators, the macOS console owner, any user other than `sandbox.workerUser`, or an unset `workerUser`. Env = the caller's minimal env (`ResolvedJobEnv`, `inheritEnv: []`) + per-attempt `TMPDIR` and (unless `keepHome` for local-login) a fresh per-attempt `HOME`; cwd = the attempt worktree (must be under `<root>/jobs`). Limits: `/bin/sh` prelude `ulimit -c 0 -n -f -u … && exec "$@"`. macOS: Seatbelt profile (decision 5); in-process egress proxy on 127.0.0.1 is the only allowed outbound destination. Windows: Job Object helper (decision 7).
5. **Seatbelt profile** (`sandbox-exec -p`, every path a `-D` parameter — never interpolated): deny all writes except the worktree, the attempt sandbox dir, `/dev/null|zero|tty*|fd`, configured runtime state dirs; deny reads of the worker data dir (device key, secrets); deny contents/listings of `<root>/{jobs,sandboxes,mirrors,.remyral}` except (`require-not`) the own worktree, sandbox dir, mirror object store and the directories leading to them; deny all reads of protected home paths (`.ssh`, `.gnupg`, `.aws`, `.config/gh|gcloud`, `.docker`, `.kube`, `.netrc`, `.npmrc`, `.git-credentials`, `Library/Keychains` (unless `allowKeychain`), cookies, Chrome/Chromium/Firefox/Brave/Edge/Safari profiles, Mail, Messages, 1Password) for the worker user's home and `protectedHomes`; deny writes to the worktree `.git` file; deny all network except outbound to `localhost:<proxyPort>`; no listening unless `allowListen`.
6. **Escaped processes.** Containers: the container is the unit (`--init`, `docker rm -f`). Host: process-group kill plus a sweep — Linux: kill processes whose initial environment (`/proc/<pid>/environ`) carries the per-spawn `REMYRAL_SANDBOX_TOKEN`; macOS (other processes' env is not readable; verified): kill orphans (ppid 1) of the worker user started after the job whose cwd is in the attempt dirs, or every recent orphan when the worker user is verified and only one host attempt runs; the rest are reported (`onEscapedProcesses`).
7. **Windows** — *superseded by p5-sandbox-ops (docs/design/p5-sandbox-ops.md §1): the job runner is `remyral-jobrun.ps1` (Job Object via PowerShell `Add-Type`), verified on real Windows 11.* Original plan (UNVERIFIED — no Windows host here; fakes only): `remyral-jobrun.exe --memory-bytes N --max-processes N --cpu-rate-percent P --kill-on-close -- cmd args` — a tiny helper to be installed with the service (p2-service-windows) that creates a Job Object (`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE | ACTIVE_PROCESS | JOB_MEMORY`, `JOBOBJECT_CPU_RATE_CONTROL_INFORMATION`), starts the runtime `CREATE_SUSPENDED`, assigns it, resumes it and waits; killing the helper closes the job handle and kills every process in the job (closes the `taskkill /T` orphan gap). Tree killer `windows-job-object` (`taskkill /PID helper /T /F`). The helper source is **not** in this change; until it exists Windows host jobs fail to start (spawn error), which is the safe direction.
8. **`runtime-sandbox`** = the host-restricted runner + runtime config, never instead of it. Builders verified against the pinned releases: Codex 0.162.1 (`thread/start.sandbox: "workspace-write"`, turn `sandboxPolicy {type:"workspaceWrite", writableRoots:[], networkAccess:false, excludeSlashTmp:true, excludeTmpdirEnvVar:false}`; `externalSandbox {networkAccess:"restricted"}` inside our container; `codex exec --sandbox workspace-write -c sandbox_workspace_write.network_access=false -c sandbox_workspace_write.exclude_slash_tmp=true`) — schema generated from the pinned binary; Claude Agent SDK 0.3.296 `options.sandbox` `{enabled, failIfUnavailable:true, autoAllowBashIfSandboxed:false, allowUnsandboxedCommands:false, excludedCommands:[], enableWeakerNestedSandbox:false, network:{allowedDomains:[], allowLocalBinding:false, allowUnixSockets:[], allowAllUnixSockets:false}, filesystem:{allowWrite:[worktree,tmp], denyWrite:[worktree/.git], denyRead:[protected]}}` — from the package's `sdk.d.ts`. `assertRuntimeSandboxNotWeaker()` rejects any weaker variant. **Not offered on macOS**: Seatbelt cannot nest (`sandbox_apply: Operation not permitted`, verified), so the runtime's own Seatbelt would fail inside ours and `host-restricted` is strictly stronger there. Offered: Codex on Linux/Windows hosts, Claude Code on Linux; never Pi/OpenCode (no sandbox), OpenHands only via `container`.
9. **Policy** (`selectProfile`): untrusted ⇒ only `container`; required profile provided exactly or refused (never substituted); must be in the effective allowed set; host profiles need the project opt-in and a ready host runner (verified identity, Seatbelt usable when required); without filesystem confinement (Linux/Pi host, Windows) a host attempt is refused while another attempt runs; `runtime-sandbox` needs the runtime in `runtimeSandboxes`; unenforced egress on a trusted host job is a note. Refusals are `SandboxUnavailableError` (`code: 'sandbox_unavailable'`, typed `reason`, `remedy`).

## Security review (residual risk per profile)

| Profile | Mitigated | Residual |
|---|---|---|
| `container` | T-SBX-1 (only the attempt mounted), T-SBX-2 (internal network, CONNECT allowlist, no published ports), T-SBX-3 (rootless engine required, no socket, no caps, no-new-privs, default seccomp, no setuid binaries in the base image), T-SBX-4 (per-attempt git dir, RO overlay of `.git`, mirror objects RO), T-SBX-5 (pids/memory/CPU/fsize/tmpfs size), T-INJ-1 (no daemon env, secrets by name only, egress = model API) | Kernel/runtime escape (shared kernel); allowlisted provider host can be used as exfil channel (inherent; tokens are per job); mirror objects of the same repository are readable (other attempts' committed work of the same project); no per-workspace disk quota on the bind mount (p4-quotas); DNS of the proxy uses the host resolver. Rootless Linux engines: uid mapping for the bind mounts (`--userns=keep-id` on Podman; Docker rootless needs the attempt dir writable by the mapped uid) **UNVERIFIED** — only Docker Desktop was tested. |
| `host-restricted` macOS (Seatbelt) | T-SBX-1 (writes confined, secrets/keychains/browser profiles/worker key unreadable), T-SBX-2 (no outbound except the proxy, no listening), T-SBX-4 (other attempts/mirror unreadable and unwritable), T-SBX-5 (nofile/fsize/nproc) | `sandbox-exec` is deprecated by Apple (functional on 26.6; re-verify each macOS update — the factory refuses host jobs if it stops working); memory/CPU not enforceable; RLIMIT_NPROC is per user; reads elsewhere on the disk are allowed (`allow default`) — the dedicated user's file permissions protect other users' data; a daemon that `chdir`s away while another attempt runs is only reported; listening (if enabled) cannot be limited to loopback; local-login (`keepHome`, `allowKeychain`) widens access to the runtime's own state. |
| `host-restricted` Windows | Dedicated non-admin user, Job Object limits and kill-on-close (helper), minimal env | **UNVERIFIED**; no per-attempt filesystem or network confinement (⇒ one attempt at a time; runtime permission policy must deny network tools); NTFS ACLs of the root/data dir are the installer's job (p2-service-windows). |
| `host-restricted` Linux/Pi | Dedicated user, rlimits, token-based sweep | No filesystem/network confinement beyond the OS user (⇒ one attempt at a time); memory not enforced — prefer `container` on the Pi (64-bit Docker/Podman). `ulimit -f` 512-byte units with dash UNVERIFIED. |
| `runtime-sandbox` | Host baseline + runtime sandbox (Codex bwrap/Windows sandbox, Claude bwrap on Linux) with tool network off and protected reads denied | Runtime sandboxes are partial (Claude: Bash only; Codex reads) — the adapters' permission policy (canUseTool / approvals) must gate the rest; behaviour on target hosts UNVERIFIED (p0-compat-handson). |

Also: the worker must call `assertTrustedGitUnchanged()` before `commit()`/`push()` (p4-git-flow wiring); a tamper is an alarm (T-SBX-4) and fails the attempt.

## Platform status

Verified: container profile on Docker Desktop 29.6.2 (linux/arm64 VM) on macOS arm64; Seatbelt on macOS 26.6 arm64; Codex/Claude config shapes against the pinned packages. **UNVERIFIED:** rootless Docker/Podman on Linux x64/arm64 (CI ticket), Raspberry Pi, Windows Job Object helper and identity check (fakes only), runtime images other than base/pi (Dockerfiles written, not built: codex, claude-code, opencode; OpenHands uses its upstream image `ghcr.io/openhands/agent-server:1.54.0-python`).

## Not in this change (follow-ups)

- Daemon wiring (`createSandboxRunners` at start, `selectProfile` per `ASSIGN_JOB`, git view + tamper check around the run) — daemon/ was owned by other agents; p4.
- The probe report still lists `sandbox.os_user_missing`; feed `createSandboxRunners().capabilities()` into `probeSandboxProfiles` (p4).
- ~~`remyral-jobrun.exe` source + installer (p2-service-windows).~~ Done differently in p5-sandbox-ops (`remyral-jobrun.ps1`).
- `JobSpec` needs `sourceTrust` and the project's host opt-in (p4-scheduler); today callers pass them into `selectProfile`.

## Rollback

Additive. The `sandbox` config key is optional with defaults; nothing calls the runners yet. Revert the commit; on a node `docker rm -f $(docker ps -aq --filter label=remyral.sandbox)`, `docker network prune --filter label=remyral.sandbox=job`, delete `<workspaceRoot>/sandboxes`.

## Operational metrics

Count `SandboxUnavailableError` by `reason`; `GitMetadataTamperedError` (alarm); egress decisions (allowed/denied by reason, per job — from the proxy's JSON lines / `onEgressDecision`); escaped processes killed/suspicious (`onEscapedProcesses`, alarm); container OOM kills (`finalState().oomKilled`); proxy start failures (`SandboxSetupError`).
