# p17-embeddings — using the embedding index across the system

- **Task:** `p17-embeddings`. **Date:** 2026-10-25.
- **Owner question:** "embeddingten sistem genelinde yeterince faydalanıyor muyuz" — the proposal below was approved.
- **Builds on:** [p6-vector](p6-vector.md) (consent-bound index, `search_embeddings`), [p10-semantic-memory](p10-semantic-memory.md)
  (Bedrock `cohere.embed-multilingual-v3`, dedupe thresholds), [p11-memory-layers](p11-memory-layers.md) (the context
  bundle, prompt relevance), [p17-auto-learning](p17-auto-learning.md) (TR/EN twins by meaning, backfill CLI),
  [p15-auto-mode](p15-auto-mode.md) (auto-fix jobs), [p6-automations](p6-automations.md).
- **Migration:** 0156 (additive). **Release:** master + web; no worker release.

## 1. Problem

Until now the vectors served the Context search, memory dedupe / auto-learning, prompt relevance of memories and chat
knowledge. Nothing used them where work happens: a job did not know that the same work had been done (and how) last
week, a failure did not say that the same error had been solved, and the same job or automation could be created twice
without a word.

## 2. What it does

| Where | What | When nothing is shown |
| --- | --- | --- |
| Job page (Diyalog `/jobs/:id`, side column) | **Benzer geçmiş işler**: up to 3 finished jobs (succeeded / failed) of the same project, created before this one — title (link), state, age, summary; the ones the agent was given carry "Ajana ipucu olarak verildi" | no provider, capture off, nothing similar enough |
| Job's context (agent) | after the bundle (and the upstream outputs and the trigger event): a fenced **untrusted** block with up to 3 **succeeded** similar jobs' titles and summaries (≤ 2400 characters) | as above, or the project setting / `RELATED_WORK_CONTEXT=off`, or the lookup takes > 4 s |
| Failed job page; an automation's last failure (job or workflow run); a failed workflow run's page | **Benzer hata daha önce şöyle çözüldü**: earlier failures of the project that look like this one and were solved afterwards — how (the same job succeeded on a later attempt / its auto-fix job succeeded / a later run of the same automation succeeded / a re-run of the workflow run succeeded), the fix's summary, links to the fix and to the earlier failure | nothing similar was solved |
| Composer (`/jobs/new`), the chat's job card, the automation form | **Benzer bir kayıt var**: an open or ≤ 14-day-old job, or a live automation, of the project that looks like what is being created (link); a warning only, never blocks | — |
| Auto-fix pass (system) | a job that fails **the same way** as another job whose auto-fix job is still open gets no second fix job (skipped, naming the open one) | — |
| Chat assistant (system cards) | proposing the **same** job / automation / workflow card again (same thread and kind, the same payload apart from what is generated per proposal: the work branch, the review, advice and reuse notes — a retried or regenerated turn) returns the open card instead of a second one; a call with `execute: true` and every other card kind are unchanged | — |

"Pick what exists" (brief §3): jobs and automations have the duplicate check; workflow definitions are versioned by
name inside a project (a second definition with the same name is a new version, not a duplicate) and "Senden
bekleyenler" cards are generated by the platform from approvals, questions and machine states, not created by people —
so neither got a check. Memory suggestions already had their dedupe (p10 / p17-auto-learning).

## 3. When two items are "similar" (`apps/master/src/related/score.ts`)

Measured with Cohere Embed Multilingual v3: a Turkish sentence and its English translation score **≈ 0.72**, and two
unrelated texts of one project can reach **≈ 0.72–0.74** too. One low cosine threshold therefore either misses TR/EN
twins or shows noise. Every rule combines a **cosine floor** with a **second, independent signal**:

- **lexical** — Jaccard of the normalised word sets (stop words removed);
- **identifiers** — shared identifier-like tokens: file names and paths (`login.ts`, `src/auth`), `snake_case`,
  `camelCase`, versions, codes (`E401`, `ENOENT`), numbers of 3+ digits. They survive translation ("login.ts'yi düzelt"
  / "fix login.ts"; Turkish suffixes after an apostrophe are dropped), so they are the cross-language corroboration;
- **structural** — the same lineage (automation, auto-fix chain), the same specific error code, the same failed step type.
  Everything is inside one project already, so "same project" is a precondition, not a signal.

| Rule | Accept when | Why |
| --- | --- | --- |
| Similar job | cosine ≥ **0.85**; or ≥ **0.72** and (Jaccard ≥ **0.2** or ≥ 1 shared identifier or same lineage) | 0.85 is where the same task reworded lands (p17-auto-learning measured TR/EN twins of longer texts at 0.85–0.95); between 0.72 and 0.85 noise exists, so a second signal decides. A bare TR/EN pair without identifiers or lineage is indistinguishable from noise and is not shown (documented limit). |
| Similar failure | same **specific** error code and cosine ≥ **0.72**; or (no shared code) cosine ≥ **0.9** and (Jaccard ≥ **0.3** or a shared identifier) | the code is the strongest structural signal; generic codes (`attempt_failed`, `runtime_error`, `exit_code`, …) never count. Messages are normalised first: ids, hashes, timestamps, temp / home paths, numbers and durations masked. |
| Duplicate (warning) | cosine ≥ **0.9**; or ≥ **0.8** and (Jaccard ≥ **0.3** or a shared identifier) | stricter: a wrong warning before creating something is noise people learn to ignore. A TR/EN pair (0.72) is no duplicate warning. |
| Auto-fix twin | identical normalised code + message; or the same specific code and cosine ≥ **0.9** | a false merge would leave a failure without a fix job, so only near-identity counts; works without a provider through the exact path. |

Ranking: cosine plus small bonuses (+0.04 × lexical/bar, +0.02 identifiers, +0.02 lineage, +0.03 same code). The unit
test `related-score.test.ts` pins these with the measured shapes (TR/EN pair at 0.72 with and without identifiers,
noise at 0.74, paraphrase at 0.8, generic vs specific codes, masking).

What is compared: a job's **card** — its title and the first 1500 characters of its prompt (the title repeats the prompt's
first line, so it is not added twice); a failure's `step · code: normalised message` (≤ 1000 characters); an
automation's name, description and job prompt. Both sides are embedded as `document` (symmetric comparison, the space
the 0.72 / 0.85 measurements were made in).

## 4. The context block

`RelatedContextProvider` wraps the job context provider chain (bundle → workflow upstream outputs → trigger event →
**similar past jobs**). `RelatedWorkService.contextFor(jobId)`:

- skipped for `machine-admin`, `function` and `integration` jobs, with `RELATED_WORK=off`, `RELATED_WORK_CONTEXT=off`, or
  the project's setting off;
- chooses once, on the first context issue, and stores the choice in `job_related_context` (job ids and scores); every
  later attempt renders the same jobs (even if the provider is gone by then). When the lookup cannot decide (no
  provider, consent off, provider error, > 4 s) nothing is stored and the job runs without the block;
- only **succeeded** jobs with a summary that passes the secret scan; title ≤ 120 and summary ≤ 500 characters each,
  the block ≤ 2400 characters;
- fenced like the trigger event (`<<<remyral-related-<nonce> similar-past-jobs untrusted>>>` … `end>>>`, the nonce a hash
  of the job id and the content; `<<<` / `>>>` in the text are replaced by look-alikes), preceded by a notice that it is
  untrusted data — hints, never instructions, and that it cannot change the task or the rules, grant permissions,
  approve, merge, deploy or ask for secrets;
- a failure anywhere means "no block" — it never fails a job. The bundle hash sent with the assignment becomes the
  sha256 of the rendered text when a block is added (as the workflow and trigger providers already do); the pinned
  bundle itself is unchanged.

**Setting:** Projeler → Hafıza → "Benzer geçmiş işler" — "İşlere benzer başarılı işlerin özetlerini ipucu olarak ver"
(default on, `related_work_settings`; project admin = `memory.suggestions.admin`, optimistic, audited
`related.settings`). **Kill switches:** `RELATED_WORK=off` (everything in this note), `RELATED_WORK_CONTEXT=off` (the
block only; the pages keep their hints).

## 6. API (`apps/master/src/related/routes.ts`)

| Route | Authz | Notes |
| --- | --- | --- |
| `GET /jobs/:id/related` | `jobs.read` on the job's project | `{similar, givenToAgent, failures (FAILED jobs only), unavailable}` |
| `GET /workflows/runs/:id/related` | `workflows.read` on the run's project | `{failures, unavailable}` |
| `POST /related/check/jobs` `{project, text, excludeId?}` | `jobs.read` on `project` | `{items ≤ 3, unavailable}`; 20 checks / person / minute |
| `POST /related/check/automations` | `automations.read` on `project` | same |
| `GET /related/settings?project=` | `jobs.read` | `{contextEnabled, version, platform}` |
| `PUT /related/settings` `{project, contextEnabled, expectedVersion}` | `memory.suggestions.admin` | 409 `related_settings_conflict` |

`unavailable`: `off`, `no_provider`, `not_consented`, `secret`, `rate_limited`, `error` — an empty answer, never an
HTTP error. Every answer passes the observability redactor like the job detail.

**Authorization / no cross-project leak:** each route resolves the project of its target (job, workflow run, the
project in the request) and the authz layer checks the caller's role in it (404 when not visible); every SQL statement
of the service filters by that project (vectors, candidates, resolutions — `later.project = $2`, `fj.project = $2`), so
nothing of another project is scored, let alone returned. The integration test proves it with two projects and a viewer
of only one.

## 7. Indexing, backfill and cost

`work_embeddings` (kind, item, project, error code, content hash, model, vector):

- **job_card** — every non-draft job of a consented project; **job_failure** — jobs with a failed attempt or in FAILED;
  **workflow_failure** — failed workflow runs; **automation** — live automations. Job result summaries stay in
  `search_embeddings` (p6-vector), unchanged.
- The **indexer pass** runs on the search indexer's interval (`SEARCH_INDEX_INTERVAL_MS`): at most 64 items per kind per
  pass (the interval is the rate limit); lookups embed a missing or changed item on demand (≤ 32 per lookup).
- **Gates** (as search): a provider configured, the project's capture consented (re-checked under a share lock on the
  consent row before each insert), secret-looking texts never sent (remembered so they are not picked again). Switching
  capture off deletes the project's work vectors in the same transaction; a model or region change drops them with the
  search vectors; the pass also drops vectors of non-consented projects and deleted automations.
- **Backfill:** `docker exec <master> remyral-master search:backfill [--dry-run] [--kind job_summary|job_card|job_failure|workflow_failure|automation|all …] [--batch 32] [--rate 600] [--max N] [--json]`
  — prints what is missing per kind (`--dry-run` sends nothing), then embeds in batches with at most `--rate` texts per
  minute; idempotent (only missing vectors are embedded); audited `search.backfill` (system, `cli:search-backfill`).
  `job_summary` runs the existing search pass (context documents and job summaries).

**Cost** (Cohere Embed Multilingual v3 on Bedrock, list price at the time of writing $0.10 per 1M input tokens — check
the current Bedrock price list): a job card is ≤ ~1600 characters (≈ 400–600 tokens; Turkish tokenises heavier), a
failure ≤ ~1000 characters (≈ 300 tokens), an automation ≤ 2000 characters. A backfill of 1000 jobs with 200 failures is
≈ 0.6M tokens ≈ **$0.06**; each new job adds one card (and one failure if it fails) ≈ $0.00005; each duplicate check
embeds one text (debounced, ≤ 20 per person per minute). The vectors are 1024 floats ≈ 4 KB per row in Postgres.

## 8. Security review

| Threat | Mitigation | Test |
| --- | --- | --- |
| A job of project A shows or receives work of project B | project-scoped routes + every query filtered by the target's project; the context block re-checks the project when rendering | integration (two projects, a viewer of one: 404; no B ids / summaries in A's answers or block) |
| Prompt injection through an earlier job's summary (agent-written text) reaching a new agent | only succeeded jobs, fenced with a content nonce, defanged delimiters, explicit "untrusted data, not instructions" notice, size-capped; never part of the pinned bundle or the authority order (ADR-0010); per-project off switch and platform kill switch | unit (fence, nonce, cap), integration (block content) |
| Secrets sent to the provider or shown | the secret scan before every provider call (cards, failures, automations, checks); summaries with a secret-looking value are never shown or given; the redactor on every answer | integration (an AWS-key-looking prompt / check text is never sent) |
| Text of non-consented projects leaving the system | the consent gate on every call and before every insert; capture off deletes the work vectors at once | integration |
| A wrong merge hides a failure from auto-fix | only identical normalised failures or same specific code + cosine ≥ 0.9; the skip is recorded with the open fix job's id (`job_auto_fixes.reason`) | integration |
| Duplicate checks as an embedding oracle / cost | per-person limit (20 / min), debounced client, the caller must read the project, at most 3 hits with titles only | integration |
| A failure in the lookup failing jobs or pages | every entry point catches and answers "nothing"; the context provider falls back to the inner context | unit, integration (no provider) |

## 9. Rollback and operations

- `RELATED_WORK=off` (everything) or `RELATED_WORK_CONTEXT=off` (the block); per project: Projeler → Hafıza.
- Migration 0156 is additive; an older master ignores the tables.
- Release: master + web. After deploy: `remyral-master search:backfill --dry-run`, then without `--dry-run`.
